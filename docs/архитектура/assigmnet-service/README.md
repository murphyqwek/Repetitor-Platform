# Assignment Service — комплект спецификаций для Codex

Редакция 27.11.2026. Стек: Java 17, Spring Boot, Gradle Kotlin DSL, PostgreSQL, Kafka, MinIO; версии и структура репозитория сверяются перед реализацией. Документы описывают проект, не готовую реализацию.

## Порядок чтения

1. [Требования](assignment_service_requirements.md) — бизнес-правила, границы MVP и явно обозначенные решения по оставшимся неоднозначностям.
2. [Модель данных](assignment_service_db_design.md) — 36 таблиц Assignment, ключи, индексы, связи, транзакции; редакция после проектирования API.
3. [Публичный REST](assignment_service_rest_api_contract.md) — маршруты, DTO, права, ошибки.
4. [Внутренний REST](assignment_service_internal_api_contract.md) — Identity, Education, аутентификация и Saga.
5. [Kafka](assignment_service_kafka_contract.md) — envelope, payload, outbox и доставка.
6. [Тестирование](assignment_service_test_plan.md) — сценарии с проверяемыми ожидаемыми результатами, включая гонки и отказоустойчивость.
7. [План для Codex](assignment_service_codex_implementation_plan.md) — порядок этапов, изменения, DoD и тесты.

Правило приоритета: последние согласованные требования и явно помеченные технические решения этой редакции имеют приоритет над прежними черновиками и примерами. Контракты REST/Kafka определяют транспорт; модель данных определяет локальные инварианты. При реальном конфликте не менять бизнес-правила молча: зафиксировать его и продолжить независимые задачи. Не использовать старые версии этих файлов параллельно с этой редакцией.

## Что ещё проверить перед кодом

- Реальные маршруты, JWT/cookie/CSRF и выпуск сервисных JWT в Identity/Education; новые внутренние операции — проект, а не подтверждение, что они уже существуют.
- Для Saga нужен дополнительный протокол tombstone освобождённых referenceId в Education (вне 36 таблиц Assignment).
- Проверить правомерность импорта РЕШУ ЕГЭ, разрешённый интерфейс, форматы и идентификаторы. Пока адаптер тестировать на локальных синтетических fixtures, не выполнять массовый сетевой импорт. Не подставлять условные экзаменационные шкалы вместо действительных.
- Родительский доступ к ДЗ и JSON-импорт преподавателя не согласованы — не включены в MVP. Остальные технические значения по умолчанию перечислены в требованиях и контрактах.

Рекомендуемое место в репозитории: `docs/assignment/`. Приложить также действующие спецификации Identity/Education. Codex получает план и **один этап за запуск**, вместе со всеми документами; итог этапа — код, миграции, тесты и отчёт с фактически выполненными командами.
