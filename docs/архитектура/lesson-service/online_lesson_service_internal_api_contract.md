# Online Lesson Service — внутренние REST-контракты

Дополнения к Identity/Education, не доказательство их существования в коде. Использовать действующие контракты Assignment для user single/batch, scopes, service auth. Не ломать Assignment. Все internal endpoints недоступны браузеру/gateway; отдельные service JWT (iss,aud,sub,tokenType=SERVICE,scope,iat,exp; TTL5min default), безопасная сеть/TLS, отсутствие пользовательских секретов. Connect timeout1s/read3s обычный JSON, один bounded retry safe read, durable jobs для mutations. Ошибка зависимости 503, не трактовать timeout как absence/empty. Нет внешнего I/O внутри долгой SQL транзакции.

## 1. Identity
Переиспользовать `GET /internal/v1/users/{userId}`, `POST /internal/v1/users/batch`, scope users:read. DTO `{id,firstName,surname,patronymic,roles,blocked,profileCompleted}`; batch request `{userIds:[...]}` ≤500 distinct, result `{users,missingUserIds}`; точное покрытие запрошенных IDs, no password/login/token. Синхронно на start/admission/token/assign/restore. Batch worker 15s для активных участников, успешный timestamp отдельно от Education. blocked/missing/role removed/profile incomplete → revoke (teacher blocked → finish), timeout → no fresh lease. Freshness ≤60s, expire closes protected APP/read/write and triggers media rotation/closure; not equivalent to kick. Resume only after fresh validation and no independent flag. Kafka event can shorten latency; stale unblock never removes kick/membership revocation. Source versions optional in REST but durable monotonic revisions recommended on events. Re-check events with current provider when out of order or stale; deny pending verification, not grant.

## 2. Education — resolve and membership
All requests service auth scope `lessons:resolve` (or `lessons:membership` for batch). POST `/internal/v1/lessons/resolve` body LessonRef (see REST). Response `{courseId,courseTitle,teacherId,startsAt,endsAt,meetingUrl,studentIds,lessonRef,resolvedAt}` for ACTIVE existing course and valid occurrence; cancelled/deleted/series stopped →404; consistent read snapshot. No implicit recurrence generation in Online Lesson. Use exact originalDate even moved date. GET/POST no mutation. Resolve endpoint does not reserve. Validate course ID matches occurrence. For stopped series previously moved original date before cutoff remains.

POST `/internal/v1/courses/membership/batch` scope `lessons:membership`, body `{courses:[{courseId,userIds:[...]}]}` (≤50 courses, ≤500 pairs per request; chunk safely). 200 `{courses:[{courseId,state:"ACTIVE"|"DELETING"|"MISSING",teacherId,meetingUrl,courseTitle,members:[{userId,enrolled}]}],resolvedAt}`; include all requested IDs even false; teacher ownership from teacherId not student membership. No current membership grant for DELETING. Online Lesson maintains timestamps per participant/lesson; if missing/deleting course, finish; excluded student revoke; new enrollment not auto assigned. Admin verified by Identity, course state required. Reserve/resolve returns only needed metadata; no cross-DB access.

## 3. Education — execution guard
New `lesson_execution_guard` (or equivalent provider-local tables): `attempt_id uuid PK` (online lesson ID), `course_id`, `lesson_type`, `single_lesson_id?`, `series_id?`, `original_date?`, `teacher_id`, `state ACTIVE|RELEASED`, `created_at`, `released_at?`, `payload_hash?`; release tombstone may contain only attemptId + course/ref if no guard existed. Partial unique per occurrence WHERE ACTIVE. Permanent RELEASED tombstone for MVP, no FK cascade from deleted course (guard must not resurrect). Lock order: serialize attempt ID via transaction advisory lock, then course/occurrence/series lock in provider; all cancel/reschedule/stop operations use compatible lock protocol. Coarse course row lock acceptable MVP; no HTTP while lock held. Stop series with guarded occurrence that would be removed returns 409; caller finishes first, no silent cancellation. Course delete is allowed and records logical event at DELETING; cannot reserve afterward.

POST `/internal/v1/lessons/execution-guards` scope `lessons:guard:write` body `{attemptId,lessonRef,teacherId}`. Under lock: verify owner, ACTIVE, occurrence exists, window now between start−15min and end; stable reservation same ID/hash returns200, new201 with resolve DTO plus `{attemptId,guardState:"ACTIVE"}`; same ID different body409, RELEASED409 GUARD_RELEASED, other guard409 LESSON_ALREADY_RESERVED. On repeat with ACTIVE guard return original stable snapshot or authoritative current snapshot (explicitly indicate revision); cancellation/reschedule impossible while active, course deletion still causes rejection of activation. GET `/internal/v1/lessons/execution-guards/{attemptId}` scope read, 200 state+ref,404 unknown. DELETE same path scope write, body-free,204 even unknown: record RELEASED tombstone atomically, don't release other attempt. Late POST after DELETE cannot re-lock. Worker retry same ID on timeout, never generates new ID. Guard release after logical finish or failed start compensation; no TTL automatically unlocking active lesson. If abandoned job operational alert and manual reconciliation only after verifying owning attempt. Course delete can leave RELEASED/ACTIVE tombstone until consumer closes; no access to course anyway.

Education mutations: PATCH/POST cancel/reschedule guard check under same lock; stop series checks affected guarded occurrence using originalDate rule; delete course logical transaction creates outbox CourseDeleted. Cap8 enrollment under course lock: count current rows (blocked still enrolled), reject 409 COURSE_STUDENT_LIMIT, existing membership idempotent semantics match provider. Migration must inspect existing oversized courses and report/remediate with user rather than silently delete students. `course.meeting_url` already exists; extend PATCH to accept `meetingUrl` HTTPS exact allowlisted Telemost host (initial `telemost.yandex.ru`), max2048, no credentials/unsafe schemes, null explicitly clears, omitted unchanged; do not dereference URL. Owner/admin only. Update Education requirements §1.3 and REST contract accordingly. Keep existing course chat unrelated.

## 4. Materials
Use existing authorized Education owner/admin GET `/materials/files/{fileId}/content` and library metadata/list in frontend. Teacher selects PDF/image, downloads through Education using current auth, PDF.js locally renders selected pages, uploads result to Online Lesson; ordinary image copied through same upload. No internal direct bucket access, no registration in material_reference or Saga, no persistent ACL grant. Admin access follows Education rights. Browser uploads cannot be distinguished from ordinary file paste; backend validates bytes and actor, not provenance. External URLs not fetched by backend. Online Lesson does not store original library file unless needed for UI (not required). Temporary copies survive original deletion until finish.

## 5. Provider tests
Guard vs cancel/reschedule/stop race: one permitted result; course delete vs start eventually closes/aborts. Duplicate reserve/release, late POST after release, timeout-after-commit, orphan guard retry; no guard after failed start compensation. Concurrent enrollment 7→8 not9; oversized existing rows migration blocker. URL validation/replacement/clear and unrelated title update. Internal routes reject user tokens, wrong issuer/scope/aud, verify batch coverage and error handling. Test actual provider contract, not only client mocks. Existing Assignment endpoints and Education chat regressions must pass. New events from Identity/Education see Kafka contract.
