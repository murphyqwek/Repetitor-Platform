# Online Lesson Service — требования

Редакция 28.11.2026. Согласованные девять блоков проектирования Tutor Platform. Это спецификация, не отчёт о реализации. Технические уточнения, внесённые при сборке документов, перечислены в §9 и README.

## 1. Назначение
Один микросервис: проведение онлайн-занятий по расписанию, LiveKit, временный чат, совместная интерактивная доска, файлы доски, посещаемость и события бизнес-метрик. Identity владеет пользователями, Education — курсами, расписанием, библиотекой и резервной ссылкой. Assignment напрямую не интегрируется. Notification и Metrics — будущие потребители событий. Никаких межсервисных SQL FK/чтения чужих БД. Курс = группа. Максимум 8 учеников в курсе (атомарное ограничение Education), один преподаватель, максимум один одновременно допущенный к конференции администратор; всего до 10 участников.

## 2. Жизненный цикл
- Только запланированные занятия: SINGLE по singleLessonId, RECURRING по seriesId + originalDate (московская исходная дата, стабильная после переносов). Education рассчитывает расписание. Отсутствие записи Online Lesson означает, что занятие не начато; пропуски преподавателя определяются по расписанию Education.
- Только преподаватель-владелец начинает урок в интервале [scheduledStartsAt − 15 мин, scheduledEndsAt). Не более одного STARTING/ACTIVE на преподавателя и одного успешно начатого урока на occurrence. Ученик не может войти до ACTIVE. Администратор может завершить, но не начать занятие.
- Урок может длиться дольше расписания, но не более 6 часов с actualStartsAt. Ручное завершение преподавателем/администратором. Непрерывное подтверждённое отсутствие преподавателя 60 минут завершает занятие, даже если комната пуста; возвращение сбрасывает таймер. Во время отсутствия студенты могут рисовать и общаться. Если присутствие UNKNOWN, отсутствие не считается подтверждённым; шестичасовой предел сохраняется.
- STARTING → ACTIVE → FINISHING → COMPLETED; STARTING → START_FAILED (не проведённый урок; компенсация и новый запуск в допустимом окне). STARTING максимум 5 мин и не позже scheduledEndsAt для перехода ACTIVE. Доска обязательна для ACTIVE, LiveKit необязателен. Повтор открытия завершённого урока запрещён.
- При STARTING/ACTIVE Education guard блокирует перенос/отмену occurrence; остановка серии не может отменить защищённое вхождение. При удалении курса/блокировке преподавателя принудительно закрыть урок. При логическом завершении закрыть доступ, зафиксировать историю и итоговую посещаемость, освободить guard, физически очистить временные данные с retry. Причины: TEACHER_FINISHED, ADMIN_FINISHED, TEACHER_ABSENT_TIMEOUT, MAX_DURATION_REACHED, COURSE_DELETED, TEACHER_BLOCKED. История и интервалы сохраняются после удаления курса. START_FAILED не публикует Started/Finished.

## 3. Участники, роли и присутствие
- Состав учеников фиксируется при запуске из Education. Преподаватель может явно назначить нового текущего ученика во время ACTIVE; не происходит автоматически. Ученики должны быть актуальными членами, иметь роль STUDENT, незаблокированный и заполненный профиль. Родителям без другой допустимой роли доступ запрещён. Администратор может подключиться и модерировать любой активный урок, но не создавать урок. Владелец курса неизменяем. Мультироли проверяются в контексте урока, не дают чужих полномочий.
- Кик закрывает весь урок (медиа, доска, чат, файлы); преподаватель/администратор может восстановить доступ после проверки членства и Identity. Исключение из курса закрывает доступ, повторное зачисление само его не возвращает. Блокировка Identity закрывает доступ; разблокировка не снимает kick/отзыв членства. При полном отзыве доступа смена поколения медиакомнаты. Максимум одна активная MEDIA и одна APP-сессия на пользователя; новая вытесняет старую. Ограничения действуют только в текущем уроке.
- Учитель/админ могут отключить чужую камеру/микрофон (не включать удалённо), запретить соответствующий источник и демонстрацию экрана. По умолчанию ученику разрешены камера, микрофон, экран, рисование, чат; принудительное выключение без отдельного запрета допускает самостоятельное включение. Поднятая рука видна всем, состояние временное. Общий запрет рисования/чата и персональный запрет независимы; оба должны разрешать действие. Админ/владелец имеют права модерации; ученик не управляет чужими правами.
- Присутствие = объединение подтверждённых APP (WS heartbeat) и MEDIA (LiveKit) интервалов, не сумма. PRESENT при любом подтверждённом подключении, ABSENT при подтверждении отсутствия обоих, UNKNOWN иначе. Храним назначение, входы/выходы, интервалы, суммарное время, количество интервалов и неизвестные интервалы; не выдаём неизвестное время за присутствие. Учитель видит свою историю, админ — всю. Учитываем и отсутствовавших; для поздно назначенного ученика знаменатель с assignedAt, при отзыве доступа отдельно фиксируется eligibility. Телемост без доски не измеряется.

## 4. Видео и резервный режим
Self-hosted LiveKit Docker, Java/Kotlin server SDK, JS client SDK. Камера, микрофон, выбор устройств, preflight, качество соединения, демонстрация экрана, авто reconnect, совместное отображение доски и видео. Записей нет. Медиа имеет отдельные PROVISIONING/AVAILABLE/UNAVAILABLE/CLOSING/CLOSED. Токен начального входа 60 с, UUID identity, только права конкретной комнаты; admin secret только backend. Автосоздание комнат и remote unmute выключены. Смена поколения при отзыве доступа и строгом запрете старого grant; старые комнаты закрываются, разрешённые клиенты переподключаются. Webhooks подписаны, дедуплицируются, сверка каждые 15 с. При сетевом разделе немедленное закрытие стороннего медиасоединения не гарантируется.

У курса одна необязательная постоянная ссылка HTTPS на Телемост, преподаватель создаёт вручную и может заменить/очистить через Education (админ также управляет курсом). Не вызываем API Яндекса. Ученикам показываем основное подключение и резервную ссылку при наличии доступа. Доска доступна по отдельному авторизованному маршруту `/online-lessons/{id}/board` независимо от LiveKit. Если LiveKit не работает с начала или упал в процессе, тот же урок и та же доска используются с Телемостом; чат на отдельной странице не показывается, его история сохраняется до завершения. Возврат к встроенному видео возможен. Отозвать уже известную внешнюю ссылку платформа не может; преподаватель контролирует доступ средствами Телемоста.

## 5. Чат
Только текст 1–4000 символов (не пустой/пробельный). Нет файлов, edit, reply, reactions, typing, read receipts, личных сообщений. Ученик не удаляет сообщения, учитель и админ удаляют и запрещают писать ученику/всем, чтение сохраняется. Запрет из постоянного чата Education не наследуется. Поздний участник читает всю историю активного урока, в отсутствие учителя писать можно. PostgreSQL, STOMP send, ACK после commit, unique lesson+author+clientMessageId, повторы с тем же payload возвращают тот же результат; soft delete до конца занятия. REST keyset 50/100, при reconnect перечитать, Kafka не используется. До 5 сообщений/с на пользователя. При завершении физически удалить все сообщения. Один экземпляр приложения/simple broker.

## 6. Доска
Одна доска на занятие, одна начальная пустая страница, максимум 50. Учитель/админ добавляют, удаляют (не последнюю), переименовывают, сортируют, очищают страницу, меняют фон, фокусируют всех участников на странице. Все могут независимо переключать страницы, pan/zoom; фокус — разовая команда, не постоянная блокировка. Нет очистки всей доски, экспорта, повторного использования и хранения после занятия. Курсоры только на своей странице, имена и стабильный серверный цвет. Редактирование чужих объектов разрешено, если объект не заблокирован учителем/админом; запрет рисования не препятствует просмотру. Undo/Redo только собственных действий при совпадении версий, не откатывает последующие изменения других. Мышь, touch, stylus, desktop/tablet/mobile.

Инструменты: перо (цвет/толщина), ластик, выделение, перемещение, текст, линия, стрелка, прямоугольник, эллипс/круг, треугольник, многоугольник. Формулы LaTeX с редактированием исходника, несколько графиков функций с масштабом, линейка с делениями/поворотом, циркуль, транспортир. Фоны: пустой, клетка, линейка, координатная плоскость с масштабом. Изображения из файла/буфера, страницы материалов Education, PDF как изображение или фон, поворот/масштаб/рисование сверху. Только учитель/админ вставляет файлы. Без внешних iframe и полноценного офлайн-режима. Excalidraw React wrapper в Angular; математика/геометрия — frontend, backend валидирует и хранит типизированные сериализованные объекты. Проверка прототипом обязательна, возможности не считаются встроенными автоматически.

## 7. Синхронизация
MongoDB authoritative, OCC по объектам: serverVersion, page revision, epoch при очистке, metadata revision отдельно. Команды CREATE/UPDATE/DELETE/RESTORE/LOCK/UNLOCK, целый пакет атомарен, конфликт версии отклоняет пакет, разные объекты не конфликтуют. CLEAR_PAGE через REST и общую очередь; tombstone до очистки/конца. operationId + actor + hash, receipt в той же Mongo transaction; ACK после commit, без Kafka. Один in-flight пакет клиента на страницу, отправка каждые 100 мс и flush завершённого действия; локальный оптимистичный UI. Курсоры/selection transient до 20/с. При reconnect приостановить редактирование, subscribe + buffer + REST snapshot, повторить неподтверждённые команды без изменения payload; gap или периодический revision mismatch → resync. Undo/Redo как условные компенсирующие операции, сброс при clear/snapshot. Один экземпляр, ограниченная очередь по lesson, общий пул, другие уроки параллельно. Mongo outage — пауза редактирования, не подтверждать неподтверждённые writes. Цель p95 end-to-end ≤500 мс в нормальной сети, не абсолютный SLA.

Лимиты: 5000 активных элементов/страницу, весь BSON ≤8 MiB включая tombstones, 256 KiB WS frame payload, 100 ops/команду, 20 команд/с/user, heartbeat 10 с, timeout 30 с. Конфигурируемы, проверяются нагрузочно. Без Redis и горизонтального масштабирования MVP.

## 8. Файлы, интеграции и метрики
MinIO существующий, приватный online-lesson-private, отдельные credentials; PostgreSQL metadata, Mongo fileId, без Base64/бинарного STOMP/публичных S3. JPG/JPEG/PNG/WEBP, 10 000 000 bytes, ≤4096×4096, 100 файлов и 200 000 000 bytes на урок включая удалённые с доски, 3 одновременных upload/user. Проверки MIME/extension/signature/размеров, SHA256 dedup per lesson. Копии материалов через авторизованный Education API; PDF.js рендерит выбранные страницы на клиенте, загружает PNG; DOCX/XLSX не вставляем. Исходник не блокируется и не влияет на копию. Учитель/админ загружает, допущенные активные участники читают. Файлы держим до конца для undo и повторного использования, без per-element reference count/DELETE API. Поздний PUT не может стать READY, orphan cleanup. MinIO отказ не мешает обычному рисованию.

Internal REST + service JWT, актуальная проверка Identity/Education на входе/выдаче токена/назначении, локальные права на частые команды, batch refresh 15 с, максимум 60 с с последней успешной проверки каждой зависимости, затем suspension. Новые входы fail closed. Kafka at-least-once outbox/inbox; входящие UserBlocked/UserUnblocked/CourseStudentRemoved/CourseDeleted/LessonCancelled/LessonRescheduled; исходящие OnlineLessonStarted/Finished/AttendanceFinalized. Не дублируем напоминания 24/7/1h Education/Notification. Технические метрики Micrometer/Prometheus/Grafana отдельно от бизнес-аналитики.

## 9. Уточнения сборки (не отдельный раунд бизнес-согласования)
- Каталог публичного API фактически 28 маршрутов (8+7+8+5). Состояние START_FAILED и guard tombstone согласованы. Не считать START_FAILED завершённым уроком; повтор только после завершения компенсации старой попытки. Резервирование получает стабильный ID попытки. Проверки времени повторно при активации.
- Семантика safety: устаревшие grant media не допускают входа в новую комнату; при недоступности LiveKit физический отзыв не атомарен. При истечении auth lease прикладная блокировка + media rotation/close; после свежей проверки разрешённым участникам выдаются новые токены. Не считать недоступность зависимости отсутствием пользователя.
- Неизвестное присутствие: сохраняем отдельную категорию интервалов и confidence; 60 мин именно непрерывного подтверждённого отсутствия. Для присутствия APP учитываем только текущую авторизованную сессию, а не факт открытия URL. Периодические наблюдения не доказывают точные границы посещения.
- При запуске roster не более 8; при замене учеников за урок исторических назначений может быть больше 8, одновременно допущенных учеников ≤8. Админский слот освобождается при уходе; история сохраняется. Поздно добавленный ученик назначается явным POST; restore не обходит актуальные проверки.
- Все конкретные DTO/коды, lease/квоты/политики retry в соседних документах — технические defaults, уточнять при проверке реального репозитория. Не изменять согласованные правила молча.
