# Identity Service — API

**Базовый префикс:** `/api/v1`

Все пути ниже указаны относительно этого префикса. Доступ к защищённым операциям определяется по текущей сессии пользователя. Access- и refresh-токены передаются в cookies.

## 1. Аутентификация

### 1.1. Вход

**Метод:** `POST`  
**Endpoint:** `/auth/login`

Авторизация пользователя по логину и паролю.

**Тело запроса:**

```json
{
  "login": "login",
  "password": "password"
}
```

**Результат:** access- и refresh-токены устанавливаются в cookies.

**Коды ответа:**
- `201 Created` — успешный вход (код указан в исходном документе; обычно для входа используют `200 OK`).
- `400 Bad Request` — неверный логин или пароль (код указан в исходном документе; для неуспешной аутентификации обычно используют `401 Unauthorized`).

### 1.2. Регистрация родителя

**Метод:** `POST`  
**Endpoint:** `/auth/register/parent`

Регистрация родителя с использованием действующего кода приглашения.

**Тело запроса:**

```json
{
  "login": "parent123",
  "password": "example-password",
  "invitationCode": "EXAMPLE12345"
}
```

**Ошибки:**
- `400 Bad Request` — логин занят; логин или пароль не соответствует ограничениям длины; код отсутствует, истёк или недействителен.

### 1.3. Проверка ссылки регистрации преподавателя

**Метод:** `GET`  
**Endpoint:** `/auth/register/teacher/{id}`

Проверяет возможность регистрации по ссылке преподавателя. Просмотр ссылки не продлевает срок её действия.

**Коды ответа:**
- `200 OK` — ссылка действительна.
- `400 Bad Request` — ссылка не существует или истекла.

### 1.4. Регистрация преподавателя

**Метод:** `POST`  
**Endpoint:** `/auth/register/teacher/{id}`

Создаёт аккаунт преподавателя по действующей ссылке.

**Тело запроса:**

```json
{
  "login": "teacher123",
  "password": "example-password"
}
```

**Ошибки:**
- `400 Bad Request` — логин занят; логин или пароль не соответствует ограничениям длины; ссылка недействительна или истекла.

### 1.5. Обновление токенов

**Метод:** `POST`  
**Endpoint:** `/auth/refresh`

Принимает refresh-токен из cookie, выдаёт новый access-токен и ротирует refresh-токен.

**Коды ответа:**
- `200 OK` — токены успешно обновлены.
- `401 Unauthorized` — refresh-токен истёк или недействителен.

### 1.6. Выход из аккаунта

**Метод:** `POST`  
**Endpoint:** `/auth/logout`

Принимает токены из cookies, отзывает refresh-токен и очищает cookies. Уже выданный JWT без дополнительного механизма отзыва остаётся криптографически действительным до истечения своего срока.

**Коды ответа:**
- `200 OK` — выход выполнен.

## 2. Пользователи

### 2.1. Получение собственного профиля

**Метод:** `GET`  
**Endpoint:** `/users/me`

Возвращает профиль авторизованного пользователя.

**Пример ответа для ученика:**

```json
{
  "id": "a550d9c4-5d78-4c4e-85bb-c77950e5c2d2",
  "login": "st-K7M9P2RX",
  "firstName": "Арсений",
  "surname": "Стариков",
  "patronymic": "Дмитриевич",
  "roles": ["STUDENT"],
  "blocked": false,
  "createdAt": "2026-11-13T14:30:00Z",
  "grade": 10
}
```

Поле `grade` возвращается, если пользователь — ученик.

### 2.2. Изменение собственного профиля

**Метод:** `PATCH`  
**Endpoint:** `/users/me`

Изменение доступных полей профиля (кроме пароля).

**Пример тела запроса:**

```json
{
  "firstName": "Арсений",
  "surname": "Стариков",
  "patronymic": "Дмитриевич",
  "grade": 10
}
```

Поле `grade` применимо к ученику. Допустимые поля для других ролей определяются требованиями к профилям.

## 3. Приглашения родителей

### 3.1. Получение действующих приглашений

**Метод:** `GET`  
**Endpoint:** `/invitations/parents`

Возвращает список действующих приглашений, созданных текущим преподавателем, с пагинацией.

**Query-параметры:**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `page` | integer | `0` | Номер страницы, начиная с нуля |
| `size` | integer | `10` | Размер страницы, максимум 100 |

**Сортировка:** `createdAt DESC` — от новых к старым.

**Пример запроса:**

```http
GET /api/v1/invitations/parents?page=0&size=10
```

**Пример ответа:**

```json
{
  "content": [
    {
      "id": 15,
      "createdAt": "2026-11-13T14:30:00Z",
      "expiresAt": "2026-11-18T14:30:00Z"
    },
    {
      "id": 14,
      "createdAt": "2026-11-12T10:00:00Z",
      "expiresAt": "2026-11-17T10:00:00Z"
    }
  ],
  "page": 0,
  "size": 10,
  "totalElements": 12,
  "totalPages": 2,
  "first": true,
  "last": false
}
```

**Правила:**
- Доступ только пользователю с ролью `TEACHER`.
- Возвращаются приглашения только текущего преподавателя.
- Не включаются использованные, отозванные и истёкшие приглашения.
- При отсутствии приглашений: `content: []`, `totalElements: 0`.
- Максимальный размер страницы — 100 элементов.

**Коды ответа:**
- `200 OK` — данные возвращены.
- `400 Bad Request` — некорректные параметры пагинации.
- `401 Unauthorized` — пользователь не авторизован.
- `403 Forbidden` — пользователь не преподаватель.

**Замечание по модели:** если хранится только `code_hash`, исходный код не может быть восстановлен из хеша. В описанном ответе возвращаются метаданные приглашений.

### 3.2. Создание приглашения

**Метод:** `POST`  
**Endpoint:** `/invitations/parents`

Создаёт новый код приглашения для регистрации родителя. Действует 5 дней.

**Заголовок:**

```http
Idempotency-Key: 7b7fbe89-8d16-4855-ae97-e964c64fc67f
```

Заголовок используется для защиты от случайного повторного создания приглашения при повторной отправке запроса.

**Коды ответа (предлагаемые):**
- `201 Created` — приглашение создано.
- `401 Unauthorized` — пользователь не авторизован.
- `403 Forbidden` — пользователь не преподаватель.

### 3.3. Отзыв приглашения

**Метод:** `POST`  
**Endpoint:** `/invitations/parents/{id}/revoke`

Преподаватель отзывает собственное приглашение. Отозвать чужое приглашение нельзя.

**Коды ответа:**
- `400 Bad Request` — приглашение не существует (согласно исходному описанию).
- `403 Forbidden` — пользователь не преподаватель или приглашение ему не принадлежит.

## 4. Регистрация детей

### 4.1. Создание заявки

**Метод:** `POST`  
**Endpoint:** `/student-requests`

Авторизованный родитель отправляет заявку на регистрацию ребёнка.

**Заголовок:**

```http
Idempotency-Key: 7b7fbe89-8d16-4855-ae97-e964c64fc67f
```

`patronymic` может быть `null`.

**Коды ответа:**
- `400 Bad Request` — некорректные данные заявки.
- `401 Unauthorized` — пользователь не авторизован.
- `403 Forbidden` — пользователь заблокирован или у него нет права создать заявку.

### 4.2. Получение своих заявок

**Метод:** `GET`  
**Endpoint:** `/student-requests/my`

Возвращает заявки текущего родителя, включая их статусы. Обработанные заявки сохраняются для истории.

**TODO:** определить формат ответа и пагинацию.

### 4.3. Получение ожидающих заявок

**Метод:** `GET`  
**Endpoint:** `/student-requests`

Возвращает ожидающие рассмотрения заявки для преподавателя или администратора.

### 4.4. Подтверждение заявки

**Метод:** `POST`  
**Endpoint:** `/student-requests/{id}/approve`

Создаёт аккаунт ребёнка, генерирует логин `st-XXXXXXXX` и пароль, связывает ребёнка с родителем, отмечает заявку обработанной. Повторное подтверждение одной заявки должно быть исключено.

### 4.5. Отклонение заявки

**Метод:** `POST`  
**Endpoint:** `/student-requests/{id}/reject`

Отклоняет заявку и сохраняет результат рассмотрения.

### 4.6. Просмотр учётных данных ребёнка

**Метод:** `GET`  
**Endpoint:** `/students/{id}/credentials`

Возвращает логин и текущий пароль ребёнка родителю, имеющему подтверждённую связь с этим ребёнком. По принятому требованию пароль доступен родителю повторно, а не только при создании аккаунта.

**Пример ответа:**

```json
{
  "studentId": "a550d9c4-5d78-4c4e-85bb-c77950e5c2d2",
  "login": "st-K7M9P2RX",
  "password": "example-password"
}
```

**Требования безопасности:** проверка связи родитель–ребёнок; отсутствие пароля в логах; `Cache-Control: no-store`; при хранении восстановимого пароля — шифрование с отдельным защищённым ключом, не открытый текст. Хеш пароля для аутентификации хранится отдельно.

## 5. Поиск пользователей

### 5.1. Поиск учеников и родителей

**Метод:** `GET`

**Endpoint:** `/api/v1/directory/users`

Поиск учеников или родителей по ФИО с использованием курсорной пагинации.

**Query-параметры:**

|Параметр|Тип|По умолчанию|Описание|
|---|---|---|---|
|`type`|string|Обязательный|`STUDENT` или `PARENT`|
|`fio`|string|Обязательный|ФИО или его часть для поиска|
|`limit`|integer|20|Количество элементов (максимум 100)|
|`cursor`|string|null|Курсор следующей страницы|

Поиск регистронезависимый, допускается частичное совпадение ФИО.

**Сортировка:**

Лексикографически, по возрастанию:

1. `surname`
    
2. `firstName`
    
3. `patronymic`
    
4. `id`
    

Сравнение ФИО регистронезависимое. `null` в отчестве при сортировке считается пустой строкой.

UUID используется для однозначной сортировки пользователей с одинаковыми ФИО.

### Пример поиска учеников

```
GET /api/v1/directory/users?type=STUDENT&fio=Иванов&limit=20
```

**Пример ответа:**

```
{
  "content": [
    {
      "id": "a550d9c4-5d78-4c4e-85bb-c77950e5c2d2",
      "firstName": "Иван",
      "surname": "Иванов",
      "patronymic": "Александрович",
      "parents": [
        {
          "id": "b550d9c4-5d78-4c4e-85bb-c77950e5c2d2",
          "firstName": "Мария",
          "surname": "Иванова",
          "patronymic": "Петровна"
        }
      ]
    }
  ],
  "limit": 20,
  "hasNext": true,
  "nextCursor": "eyJ2IjoxLC..."
}
```

### Пример поиска родителей

```
GET /api/v1/directory/users?type=PARENT&fio=Иванова&limit=20
```

**Пример ответа:**

```
{
  "content": [
    {
      "id": "b550d9c4-5d78-4c4e-85bb-c77950e5c2d2",
      "firstName": "Мария",
      "surname": "Иванова",
      "patronymic": "Петровна"
    }
  ],
  "limit": 20,
  "hasNext": false,
  "nextCursor": null
}
```

### Получение следующей страницы

Клиент передаёт `nextCursor` из предыдущего ответа:

```
GET /api/v1/directory/users?type=STUDENT&fio=Иванов&limit=20&cursor=eyJ2IjoxLC...
```

Сервер возвращает следующие элементы после позиции, указанной в курсоре.

**Правила:**

- Курсор содержит информацию о последнем возвращённом пользователе и является непрозрачной строкой для клиента.
    
- Курсор должен использоваться с теми же фильтрами `type` и `fio`, с которыми он был выдан.
    
- Если следующей страницы нет, `hasNext = false`, `nextCursor = null`.
    
- Если пользователей не найдено, возвращается пустой массив `content`.
    
- Общее количество пользователей и страниц не возвращается.
    
- При поиске учеников дополнительно возвращается список их родителей.
    
- При поиске родителей возвращаются только ID и ФИО.
    
- Логины, пароли и остальные персональные данные в результат поиска не включаются.
    
- Доступ к поиску предоставляется авторизованным преподавателям в рамках разрешённых учебных сценариев.
    

**Ошибки:**

- `400 Bad Request` — некорректные параметры поиска или курсор.
    
- `401 Unauthorized` — пользователь не авторизован.
    
- `403 Forbidden` — недостаточно прав для поиска.

## 6. Администрирование пользователей — добавленный endpoint

### 6.1. Изменение статуса блокировки пользователя

**Метод:** `PATCH`  
**Endpoint:** `/admin/users/{id}/status`

Администратор блокирует или разблокирует аккаунт пользователя.

**Тело запроса:**

```json
{
  "blocked": true
}
```

Чтобы разблокировать пользователя, передать `"blocked": false`.

**Предлагаемые коды ответа:**
- `200 OK` — статус изменён.
- `400 Bad Request` — некорректное значение статуса.
- `401 Unauthorized` — пользователь не авторизован.
- `403 Forbidden` — нет роли администратора.
- `404 Not Found` — пользователь не найден.
