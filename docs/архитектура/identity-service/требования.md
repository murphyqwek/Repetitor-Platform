# Описание сервиса
Сервис нужен для регистрации учеников, родителей и преподавателей

Также он нужен чтобы забанить пользователя

Также он занимается refresh токенами, а точнее их обновлением
# Регистрация преподавателя
Администратор через свою панель создает временную ссылку для регистрации преподавателя. Ссылка действует 1 день. Администратор может отозвать ссылку

Эту ссылку может сделать только администратор, поэтому нужно будет проверить его роль

С точки зрения сервиса - создается уникальный id для этой ссылки. Пользователь переходит по ссылке, где в url будет этот id. Сервис проверяет этот id - истек ли его срок или нет. Потом он вводит свои данные и сервер создает запись и выдает роль учителя

ВАЖНО - когда пользователь заходит на страницу, мы никак не будем продлевать эту ссылку.

ВАЖНО - после регистрации родитель ДОЛЖЕН указать свои ФИО, иначе он не сможет пользоваться платформой

# Создание кода преподавателя
Преподаватель заходит в свой кабинет и отправляет запрос на создание кода приглашения. Он может видеть свои активные коды и в случае чего отозвать их. Код действителен 5 дней с момента создания

Код состоит из 12 случайных заглавных букв латинского алфавита и цифр. Перед тем, как его сохранить  мы должныы проверить,  что такого кода нет в базе данных

Истекшие коды мы будем удалять. Препод не может увидеть уже истекшие коды

ВАЖНО - после регистрации преподаватель ДОЛЖЕН указать свои ФИО, иначе он не сможет пользоваться платформой
# Регистрация родителя
Родитель заходит на сайт, регистрацию. Он вводит логин и пароль. Система принимает принимает только 1 пароль, то  есть бекенд не будет ожидать от фронтенда подтверждение пароля, этим будет заниматься фронтенд. Пароль минимум 8 символов. Если логин уже существует, то возвращаем ошибку 400 и текст - пользователь с таким логином существует.

При регистрации он вводит действующий код преподавателя. Если кода нет или он истек бекенд возвращает 400 код и текст - Код приглашения истек, либо не существует

После успешной регистрации выдаем роль Родителя

# Регистрация ребенка
Авторизованный родитель заходит в свой профиль и оформляет запрос на добавление ребенка на платформу:

В заявке он указывает его ФИО и класс. Заявка отправляется на сервер и сохраняется. Потом администратор или учитель может посмотреть заявки - ему доступен ФИО ребенка и id родителя. Преподаватель может подтвердить заявку, тогда создается аккаунт ребенка - случайным образом создается логин и пароль. 

Родитель может видет состояние  заявки - рассматривается, подтверждена и отклонена. Если заявка подтверждена, то родитель может  посмотреть логин и пароль и ФИО ребенка.

Преподаватель и администратор видит только заявки, которые ожидают подтверждения, они не могут посмотреть пароли и логины от детей. Родитель видит только свои заявки и уже подтвержденных детей

Точнее, если заявка принята, то регистрируется ребенок, заявка меняет свой статус и туда записывается id ребенка из app_user

Причем пароль будет хранится в отедльной таблицу student_profile
## Формат логина

`st-XXXXXXXX` - где X - либо заглавная латинская буква,  либо цифра

# Access Token
После успешной регистрации, мы сохраняем пароль  в захешированном виде,  выдаем нужную роль и возвращаем в HttpOnly куках access jwt (для этого  будем использовать ассиметричное шифрование, в .env есть JWT_PRIVATE_KEY_PATH - путь до приватного ключа формата .pem) и refresh token в виде uuid или другой случайно  сгенерированной строки. access token должен истечь через 15 минут. Refresh токен живет в Redis, у него TTL 7 дней

# Logout
Мы должны удалить refresh токен из редиса и удалить из  куков access token и refresh 

# Created at

После успешной регистрации мы также  сохраняем дату и  время создания аккаунта в формате, с которым удобно будет работать с time zone - например Instant

# Получение родителей и учеников
Преподаватель может получить список учеников и их родителей. Например, на зачисление на курс. Этот сервис занимается тем, что предоставляет список родителей и учеников. Отдельный список должен быть для учеников, где у ученика будет ещё и родителей

Во всех этих поисках нужно возвращать ФИО, статус блокировки и роль

# Длина паролей и логина
Для родителей и учителей:

Логин - минимум 5 символов, максимум 25
Пароль - минимум 8 символов, максимум 25
